# 데이터 구조 설명

단가마다 성격이 달라서 저장 형태를 네 가지로 나눴습니다.
모든 파일은 `meta`(출처·기준일 등 꼬리표)와 실제 데이터로 이루어집니다.

---

## 1. 전기요금 — `data/electricity/kepco_YYYY-MM-DD.json`

### 왜 이렇게 나눴나

한전 요금표는 계약종별마다 요금 구조가 다릅니다.

- **주택용**은 쓴 양에 따라 단가가 올라가는 **누진제**
- **일반용(갑)·교육용(갑)**은 **계절별** 단가
- **일반용(을)·산업용(을)**은 **계절 × 시간대(경/중간/최대부하)** 단가

하나의 표에 억지로 욱여넣으면 빈칸투성이가 되므로, **요율 한 줄(rate line)** 단위로 쪼갰습니다.
`rate_structure` 값이 그 종별이 어떤 구조인지 알려줍니다.

| `rate_structure` | 뜻 | 해당 종별 |
|---|---|---|
| `progressive` | 누진제 | 주택용전력 |
| `seasonal` | 계절별 | 교육용(갑), 일반용(갑)Ⅰ, 산업용(갑)Ⅰ, 심야전력 |
| `time_of_use` | 계절 × 시간대 | 교육용(을), 일반용(갑)Ⅱ·(을), 산업용(갑)Ⅱ·(을), 주택용 계시별 |
| `flat` | 단일 단가 | 가로등 |
| `mixed` | 혼합 | 농사용전력 |

### 주요 항목

```jsonc
{
  "meta":   { "source_file": "원본 PDF 경로", "published_label": "2026년 4월 16일 시행", ... },
  "taxes":  { "vat_rate": 0.10, "power_industry_fund_rate": 0.027 },
  "surcharges": {
    "climate_charge_won_per_kwh": null,     // 기후환경요금 단가
    "fuel_adjustment_won_per_kwh": null     // 연료비조정단가
  },
  "definitions": { "voltage_classes": [...], "seasons": [...], "time_zones": {...} },
  "tariffs": [
    {
      "id": "general-b",
      "contract_type": "일반용전력(을)",
      "contract_power": "계약전력 300kW 이상",
      "rate_structure": "time_of_use",
      "effective_from": "2026-06-01",
      "rates": [
        {
          "voltage": "고압A", "option": "선택Ⅱ",
          "basic_charge": 8320, "basic_charge_unit": "원/kW",
          "energy": [
            { "season": "여름철", "time_zone": "경부하", "charge": 87.3 }
            // ... 계절 3 × 시간대 3 = 9줄
          ]
        }
      ]
    }
  ]
}
```

### ⚠️ 꼭 알아야 할 두 가지

1. **`climate_charge_won_per_kwh`(기후환경요금)와 `fuel_adjustment_won_per_kwh`(연료비조정단가)는 `null` 입니다.**
   한전 요금표 PDF에 *부과방식만 적혀 있고 단가 숫자가 없기 때문*입니다.
   추측해서 넣지 않았습니다. **이 두 값 없이는 실제 전기요금을 계산할 수 없습니다.**
   한전 공지(한전ON)에서 확인해 직접 채워 넣어야 합니다. 연료비조정단가는 분기마다 바뀝니다.

2. **시행일이 종별마다 다릅니다.**
   2026-04-16 요금표의 경우 산업용전력(을)·전기자동차 충전전력요금만 4월 16일 시행이고,
   나머지 종별은 **6월 1일 시행**입니다. 그래서 `effective_from` 을 종별마다 따로 두었습니다.

### 연도별로 바뀌는 것은 요율만이 아니다

`definitions.time_zones`(계절별 시간대 구분)와 `discounts`(할인 제도)도 개정 때 바뀝니다.
2025-04-01 → 2026-04-16 사이에 여름철·봄가을철의 중간부하/최대부하 시간대가 통째로 바뀌었고,
산업용(을) 주말 할인이 새로 생겼습니다. 시간대가 바뀌면 같은 요율이라도 연간 전기요금이 달라지므로,
직전 연도 JSON을 복사할 때는 숫자뿐 아니라 이 두 항목도 해당 요금표에서 다시 확인해야 합니다.

### 전기요금 계산식

```
전기요금  = 기본요금 + 전력량요금 + 기후환경요금 + 연료비조정요금
청구금액  = 전기요금 + 부가가치세(10%) + 전력산업기반기금(2.7%)
```

## 2. 가스요금 — `data/gas/`

두 종류입니다.

### 용도별 도매요금 — `kogas_도매요금_YYYY-MM-DD.json`

특정 시점의 용도별 단가 스냅샷입니다. 단위는 **원/MJ**.

```jsonc
{ "sector": "도시가스발전용", "use": "연료전지용", "season": "단일요금",
  "feedstock_cost_won_per_mj": 22.9669,   // 원료비
  "supply_cost_won_per_mj": 0.6804,       // 공급비용
  "wholesale_price_won_per_mj": 23.6473 } // 도매요금 = 원료비 + 공급비용
```

`scripts/validate.py` 가 **원료비 + 공급비용 = 도매요금** 이 맞는지 자동으로 검사합니다.

### 발전용 천연가스요금 월별 — `kogas_발전용천연가스요금_월별.json`

2008-01 ~ 2022-12 월별 시계열입니다. 원/Nm³ 와 원/GJ 두 가지 단위로 들어 있습니다.

> 📌 이 자료는 **2022년 12월에서 끊겨 있습니다.** 공공데이터포털 원본 파일 자체가 거기까지입니다.
> 이후 자료가 필요하면 API로 최신본을 받아야 합니다.

## 3. 신재생에너지 장비 단가 — `data/renewable-equipment/장비단가_YYYY.json`

VE·경제성 분석에서 가장 많이 틀리는 지점이 **"이 단가에 설치비가 포함인가 아닌가"** 입니다.
그래서 `cost_type` 과 `scope` 를 필수로 두었습니다.

```jsonc
{
  "slug": "pv-module-mono-550w",   // 바뀌지 않는 식별자 (영문, 하이픈)
  "category": "태양광",             // 태양광 | 태양열 | 지열 | 연료전지 | 풍력 | ESS | 수열 | 바이오
  "subcategory": "모듈",            // 모듈 | 인버터 | 구조물 | 히트펌프 | 천공 ...
  "name": "결정질 실리콘 모듈",
  "spec": "단결정 550W급",
  "cost_type": "자재비",            // 자재비 | 설치비 | 턴키(합계)  ← 셋 중 하나
  "unit_price": 450000,
  "price_unit": "원/kW",            // 원/kW | 원/m2 | 원/m | 원/식
  "scope": "모듈 공급가, 운반·설치 제외",   // 단가에 뭐가 포함되는지 한 줄로
  "base_date": "2026-01-01",       // 이 단가의 기준일
  "source": "○○社 견적서 (2026.1)",
  "source_type": "견적",            // 견적 | 고시 | 실적 | 문헌
  "note": ""
}
```

같은 품목의 단가가 해마다 바뀌면 **`slug` 는 그대로 두고 `base_date` 만 다르게** 추가합니다.
그러면 연도별 단가 추이가 그대로 쌓입니다.

## 4. 기타 단가 — `data/misc/기타단가_YYYY.json`

위 분류에 안 들어가는 단가(인건비, 배관·덕트 자재, 단열재 등)를 담습니다.
`cost_type`·`subcategory`·`scope` 가 없는 것 말고는 3번과 같습니다.

## 검증 도구가 잡아주는 것 / 못 잡는 것

| 도구 | 잡아주는 것 |
|---|---|
| `scripts/validate.py` | 필수 항목 누락, 날짜 형식, 숫자 아닌 값, 중복 id, 가스 요금 합계 불일치 |
| `scripts/verify_electricity.py` | JSON에 적은 숫자가 **원본 PDF에 실제로 있는지** 전수 대조 |

> ⚠️ `verify_electricity.py` 는 *숫자의 존재*만 확인합니다.
> 예를 들어 여름철 값과 겨울철 값을 **서로 바꿔 적은 경우**는 둘 다 PDF에 있으므로 통과합니다.
> 그래서 숫자를 처음 옮길 때는 PDF를 이미지로 띄워 **눈으로 한 번 더 확인**하는 절차를 함께 씁니다.
